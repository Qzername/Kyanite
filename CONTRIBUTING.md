# Contributing

Contributions are welcome from everyone. 

Note that in this project, we focus a lot on code readability. Code must be clear at a glance for human readers, or contain well-written comments.

### Bug Fixes

If you spot a bug, feel free to open a pull request with a fix. Please make sure your PR clearly explains:
- Steps to reproduce the issue.
- A concise summary of how the fix resolves it.

### New Features

Before investing time in building a new feature, please open an issue to discuss it first. This helps ensure the idea aligns with the project's direction and avoids possibly duplicated effort.

### AI-Assisted Contributions

AI-assisted code is welcome, provided there is a human in the loop. Fully autonomous AI agent PRs are not accepted - we expect an actual developer to review feedback and engage in code discussions.

If you use AI tools to generate code or PR descriptions, please adhere to the following rules:

* **Review your own code:** Make sure you have read, tested, and fully understand every line generated by your tools before submitting.
* **Keep PR descriptions concise:** Do not paste walls of AI-generated text for a simple change. Summarize the *why* and the *what* - maintainers can read the diff themselves, so avoid line-by-line English translations of the code or repetitive phrasing.
* **Write succinct comments:** Only add code comments where logic isn't immediately obvious. Avoid verbose, multi-line LLM explanations detailing why the old code was broken.

PRs that appear unreviewed or ignore these guidelines will be closed without review.
